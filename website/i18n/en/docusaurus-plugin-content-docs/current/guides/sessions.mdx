# Session Replay

`aib session-bench` treats each JSONL file as one session: requests within a file run sequentially while sessions run concurrently up to `--max-concurrency`.

## Session Format

`sessions/session-01.jsonl`:

```jsonl
{"messages":[{"role":"user","content":"My name is Alex."}],"max_tokens":64}
{"messages":[{"role":"user","content":"My name is Alex."},{"role":"assistant","content":"Hello, Alex!"},{"role":"user","content":"What is my name?"}],"max_tokens":64}
```

## Run Replay

```bash
aib session-bench 'sessions/**/*.jsonl' \
  --base-url http://127.0.0.1:30000 \
  --model your-model \
  --max-concurrency 16 \
  --num-warmup-sessions 0 \
  --disable-flush-cache \
  --metric-path session-metrics.jsonl
```

- By default, the first 3 sessions are warmup-only; pass `--num-warmup-sessions 0` for small workloads.
- `--request-rate` controls both session arrivals and inter-turn spacing.
